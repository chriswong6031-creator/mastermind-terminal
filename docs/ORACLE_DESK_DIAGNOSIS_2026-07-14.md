## TL;DR

The Sell/Bearish prints on the NVDA/GOOGL cards are **not live bearish calls**. They are:

1. **GOLDEN ORACLE: Sell** — a **stale, inherited manifest row from a dead run** that *contradicts the system's own current state*. The live slices say NVDA `last_signal=REBUY` / GOOGL `last_signal=BUY`, `position_hint=long`; GOOGL's live backtest is currently **LONG** (entry 2026-04-14 @ 336.02). The card shows a SELL with no date because the manifest row carries no date and was inherited from an older run.
2. **RESEARCH DESK: Bearish** — a **semantic mistranslation** of a 9/100-conviction "no buy setup / unconfirmed bounce, don't chase" entry-timing read (band=`low`, entry=`bounce_wait`), built from Friday 07-10 data across the 2-day rally. Upstream had already flipped to `neutral` on 07-13; the nightly 21:30 UTC cron should clear the row to Neutral.

Neither engine "failed to identify bullish signals." The **display pipeline** failed: dateless stale verdicts, cross-lane inconsistency, and a timing read labeled as a directional call.

## The three verified bugs

1. **Manifest inheritance / cross-lane inconsistency (the real data bug).** manifest verdict ≠ slice state ≠ backtest position, live, on the same host. The `macro-multimarket` universe lane preserves dead rich rows; no invariant checks manifest == slice == backtest at publish time.
2. **Code/data version skew.** Current `signal_layer/contracts.py` emits SELL only from v2 `sell_confirms` (:136-137, :202-224), but `ingest/build_polygon_universe.py:166-168` never passes `v2=` — **a rebuild on HEAD emits zero flagship SELLs**. Shipped SELLs carry the retired CS reason vocabulary (`macd_bear_cross/recent_s1/extended`), proving live data predates the code. VPS `/opt/terminal` ingest also shows deploy lag (live intel top-level asof ≠ tape.asof, unproducible by repo HEAD).
3. **Silent no-op refresh.** `ingest/refresh_fund.sh:228-232` runs `pull_macro_intel.py --all`, but the script has no argparse — `--all` is treated as a symbol and skipped; the Mac lane's US-intel rebuild writes zero files. US intel comes solely from the VPS nightly (`30 21 * * *` UTC, macro repo `app/deploy/terminal-refresh.sh:97`).

## What is working as designed (and must not be "fixed" by curve-fitting)

- The oracle's SELL **requires over-extension by construction** (`confluence.py:291` — %K≥80 or RSI14≥70 within 8×3D bars is mandatory; :284/:289 let overbought %D substitute for the weekly-bear confirm). It is a mean-reversion timing overlay; it will always fade winners near highs. Its measured record (slices, fixed=True, 3bps): NVDA 1.13× vs 10.24× B&H (11% capture, 9 trades), GOOGL 0.87× vs 2.06× (3 trades, wr 1.0, pf null — small-sample). Honest as a risk overlay; never designed to answer "is this a good hold."
- The strong-bull hold exists **only in sim paths** (`confluence.py:343`, `confluence_v2.py:72`, `backtest.py:72`) — never on the emitted/display stream. NVDA/GOOGL's June SELLs failed `strong_bull` anyway (mo_bull = prior *closed* month was false).
- Desk lean is **not an LLM**: `_map_ai_dir` in `ingest/pull_macro_intel.py:204-226` maps band×entry deterministically; band=`low` alone forces BEAR (:218). The 5-day gate (:72, :306-314, :343, :359-362) is calendar-day and was legally passed (4 days).
- GOOGL's green **SNIPER WASHOUT** chip (`analysis.sniper.w2_washout=true`, w2_stoch_d 12) is a *bullish* dip-regime flag — internally coherent, not part of the failure.
